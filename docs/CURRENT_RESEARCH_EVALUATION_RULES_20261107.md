# レース探偵：現行モデル維持・的中率と回収率の同時評価ルール

最終更新：2026-11-07

**この文書は利用者による最新の明示指示です。** 次回以降の研究・運用相談・実装・レポートでは必ず最初に確認してください。過去の単勝限定探索、単独の的中率検証、古い「ROI 200％」「最低5レース固定」の*研究提案*との矛盾は、この文書で解消します。ただし、**現在実装済みの本番5レース・凍結済みモデルや購入履歴を、文書更新だけで書き換えることはありません。**

## 1. モデルを一から作り直さない

- 現行本番は、既に実装・学習・本番導入された `ten-year-completed-model`。56特徴量・500木のLightGBMモデルが存在し、`models/ten-year-completed-model.txt` と `config/ten-year-completed-model.json` が正本です。
- **「高回収率がまだ実証されていない」ことは「モデルが存在しない・未完成で一から再構築が必要」という意味ではありません。** 既存モデルを基点に問題を切り分けます。
- ユーザーからモデルそのものの変更依頼がない限り、学習済み重み・特徴量・モデル構造・同日／30日補正を勝手に再学習、再構築、入替しない。
- 改善対象はまず既存モデルの確率較正、出力の活用、全券種組合せ確率、券種選択、JRA公式オッズとの乖離、レース順位、買い目点数、コース別資金配分、締切・オッズ・払戻のデータ品質です。**モデル自体を変える必要性が独立に確認されるまで新モデル探しへ戻らない。**
- README/HANDOFFの「完成モデル」は実装・運用基盤の状態。過去の431.65％はインサンプル寄りの後方集計であり、将来の400％ROIを証明する意味ではありません。検証不足を理由に学習済みモデルの存在を無視しない。

## 2. レース数：毎会場最低3、原則5

- **各JRA開催日×各会場、必ず最低3レースを選ぶ研究条件。基本は従来どおり5レース。** 3、4、5レースを並行に比較できるが、1・2レース集中や0件見送り戦略を採用候補にしない。
- 現在の本番動作は5レース／会場・日であり、**研究上3レース以上を許すことは、本番を勝手に3レースへ減らす許可ではない。** 原則5レースを優先し、変更する場合は新規の因果検証と本番安全確認が必要。
- 元の選定結果から結果を見て勝ちレースだけを拾うことも、対象会場・開催日を実績が良いものだけへ絞ることも禁止。
- 対象日の一部レースのデータが欠けた場合は欠損を別計上し、全期間達成の証拠としない。

## 3. 券種は勝手に固定・除外しない

- **必ず6券種すべてを検討対象に含める：単勝・ワイド・馬連・馬単・3連複・3連単。**
- 6券種から異なる2券種を選ぶ**15通りの組合せ**を偏りなく候補に含める。特定の単勝＋ワイドだけを「正解」として固定してはいけない。
- 各券種内の組合せ、確率、公式オッズ帯、レースごとの最適券種・組合せの相互作用、1券種内の購入点数や券種間の予算配分も比較する。既存本番は1レース異なる2券種の2点であり、研究がこの仕様を無断で変更することはできない。
- 最初に使うのは実際に利用できたJRA公式の該当券種のオッズ。単勝オッズでワイド・馬連・3連単等の「架空の払戻オッズ」を作らない。存在しない過去T−15オッズを「取得済み」と称さない。

## 4. 【絶対】的中率と回収率をセットでしか評価・報告しない

**禁止：的中率だけ、または回収率だけの研究結果・推奨・優劣判断・達成宣言。** 2つは同一のレース集合、同一の発走前確定買い目、同一の対象期間・予算・精算データから*必ず対で*計算する。いずれかが再計算不能なら**「両指標を同条件で判定できない」**と説明し、片方だけを成果として推さない。

セットで必須の記載：
1. **的中レース率**＝異なる2券種のうち1点以上の実際の払戻があるレース数／有効な購入対象レース数。加えて券種別・馬券点数別的中率、**3／3・4／4・5／5全レース的中の会場・開催日数**も示す。
2. **回収率**＝同じ有効レースの**JRA実払戻合計÷実購入額合計×100％**。購入額、払戻、損益、コース別ROIも併記。未購入・未確定分を勝手に分母から消して全運用ROIのように見せない。
3. 同じ評価対象について**利益が出たレースの割合、期間別（各月・各開催日・会場）両指標、最大払戻1件を除いたROI、少数の巨大配当への依存、対象レースの欠損・遅延・未確定件数**を確認。
4. 「的中率を上げるために低オッズに偏って赤字」「ROIを上げるためにほとんど当たらない高配当一点張り」の**両方を不合格とする**。単一の最適化スコアで片方を隠さず、的中率×回収率の二軸を並列判定する。
5. ROI目標は利用者の最新希望である**400％**。目標値と検証済みの実績は厳格に区別し、400％の将来達成・継続を保証しない。過去実績を見て決めた条件の「400％」は本番認定の証拠にしない。

## 5. 実運用の改変禁止と検証方法

- 研究→同じ事前ルールを時系列別期間→**未来の実開催で、事前確定した券種・買い目とT−15までのJRA公式オッズ**→JRAの実払戻で**両指標を同時判定**。使ったデータ・対象母集団・日付・凍結時刻を記録。
- 研究だけ成功、CIだけ成功、PRマージ、Workersデプロイ成功を「400％達成」や「改善完了」と呼ばない。
- 公開済み過去買い目・履歴・D1を後から書換えない。発走15分前の締切を破らず、Primary/Backupの既存運用とCloudflare無料枠・Quotaに配慮する。
- 既存本番の学習済み重みを保持し、候補方式はまず本番買い目を変えないシャドーで検証する。ユーザーが明示していない推論コード・券種・予算・公開表示の変更は禁止。
- 利用者への報告で片方しか検証できていない場合は**数値の片側だけを成果として報告しない**。検証不能の範囲と不足資料を説明する。
