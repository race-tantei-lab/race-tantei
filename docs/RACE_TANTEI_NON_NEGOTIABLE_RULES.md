# レース探偵・絶対条件

最終更新: 2026-08-08

この文書は、ChatGPTの会話履歴が欠落しても参照できるようにGitHubへ恒久保存する。今後の分析・実装・本番反映では、この文書と `config/race-tantei-fixed-constraints.json` を最優先する。

## 1. 購入対象レース数

- 各開催日・各会場で、購入対象を5レース未満にしてはならない。
- 5レースは最低数であり、6レース以上に増やすことは認める。
- 回収率を見かけ上高くする目的で、対象レース数を5未満へ絞ることは禁止する。
- ROI閾値を理由に対象レースを0件または5件未満へ落として完成扱いすることは禁止する。

## 2. コースと購入額

- ライト: 1レース2,000円
- スタンダード: 1レース5,000円
- プレミアム: 1レース10,000円
- 各コースは指定額を使い切る。
- 3コースを同一の買い目構成へ固定する必要はない。各コースの予算に応じて点数・資金配分は変えてよい。
- 買い目点数は固定しない。
- 点数は、各コースの予算・実オッズ・データ漏洩禁止など他の固定条件を守る範囲で、レースやポリシーごとに可変とし、モデル探索の対象にしてよい。

## 3. 券種と買い目の分散

- 券種はレースごとに可変とする。
- 単勝・ワイド・馬連・馬単・3連複・3連単の6券種から、そのレースで期待回収率を下げにくい券種を事前情報だけで選択してよい。
- 毎レースすべての券種を買う必要はない。回収率を大きく悪化させると予測された券種は、そのレースでは外してよい。
- ただし1種類だけの券種へ絞ることは禁止する。各購入対象レースで最低2種類の異なる券種を含める。
- 券種の採否はレース結果を見た後に変更してはならず、必ず事前情報・公式オッズ・固定済みモデル出力だけで決定する。
- 高配当1点だけへ資金を集中させ、回収率を作ることは禁止する。
- 券種ごとの点数配分と資金配分は固定せず、モデル出力に応じて可変としてよい。

## 4. オッズと検証データ

- 買い目選定に使うオッズは、JRAが公開した実オッズだけとする。
- 単勝オッズから他券種のオッズを計算する処理、想定オッズ、推定オッズは禁止する。
- 取得できない過去オッズを後から補完・推測・捏造してはならない。
- 精算はJRAの実際の払戻金だけを使う。
- 結果、着順、払戻金を見た後に条件を決める後付け最適化は禁止する。

## 5. 季節性と検証設計

- 競馬場、馬場、出走馬構成、クラス構成などは季節・開催時期で変化するため、最後の数か月だけを唯一の完成ホールドアウトとして使わない。
- 完成判定用ホールドアウトは `config/season-stratified-holdout-v1.json` で固定する。
- 分割単位はレースではなく開催日 `raceDate` とし、同じ開催日の全レースを同じ側へ置く。
- 2024-05から2026-08まで各年月ごとに約20%の開催日を、払戻・着順などの結果を一切使わない固定SHA-256方式で選ぶ。
- レース単位の完全ランダム分割は禁止する。
- ホールドアウト日の結果を、その日の予測、条件発見、ルール選択に使ってはならない。
- ホールドアウト日の予測に使える履歴は、その開催日より前に確定している情報だけとする。未来の日付から過去を予測することは禁止する。
- 初期期間で学習履歴が不足する場合は、事前固定したコールドスタート方式を使い、評価から除外しない。
- 開催日・季節性をモデル入力に含める。少なくとも calendarYear、calendarMonth、dayOfYearSin、dayOfYearCos、daysSinceArchiveStart、seasonQuarter、venue を含める。
- 過去に末尾期間だけで行ったホールドアウト結果は診断記録として残してよいが、新しい完成判定の唯一のホールドアウトには使わない。
- 新しい季節層化分割へ移行後は、旧開発データ全体から発見済みの具体的な歪みルール値をそのまま持ち込まず、新分割の訓練側だけから再発見する。

## 6. 完成条件とモデル名

- 回収率200%以上は目標ではなく完成条件とする。
- 200%未満の探索物はモデルとして扱わない。
- 探索途中の候補にはバージョン番号を付けない。
- `v16` という名称は、全条件と全ゲートを通過した完成物にだけ付与する。
- 現在までに `v16` と名付けられていた未完成候補は、すべて内部探索物として扱う。
- 完成判定の全期間回収率は、利用可能な最初のレースから最新の終了済みレースまでを漏れなく含める。
- 過去検証の全期間回収率と、季節層化・開催日単位の固定ホールドアウト回収率の両方で、ライト・スタンダード・プレミアムの全コースが200%以上でなければ完成としない。
- 季節層化ホールドアウトは各コース100レース以上を必要とする。
- 最大払戻1件を除いた回収率が各コース100%以上でなければ昇格しない。
- 最低レース数、最低2券種、固定購入額、公式オッズ限定、データ漏洩禁止、全期間カバレッジの全条件を同時に満たす必要がある。
- 先に本番モデルを実装してから回収率を確認する進め方は禁止する。
- 条件を満たす候補が見つかるまで、完成・成功・v16とは言わない。
- 数値の捏造、結果からの逆算、条件の後付け変更は禁止する。

## 7. 探索と本番昇格

- 開発用コードで無番号の内部探索を行う。
- 固定DBを先に分析し、回収率200%以上を生む再現可能な市場の歪みを発見して一般化する。
- 買い方パターンの総当たりをモデル探索の中心に置かない。
- 不合格探索物は内部記録してよいが、本番コード・本番設定・本番買い目へ反映してはならない。
- 不合格結果を逐一ユーザーへ並べて報告しない。探索を続けるための内部情報として扱う。
- 全ゲートを通過した探索物だけを昇格処理へ渡し、昇格時に初めて `v16` を付与する。
- 自動昇格処理は、固定条件の機械検証を通過しない限り本番ファイルを変更してはならない。

## 8. 報告と進行

- 作業を始める前に、これから行う内容を説明する。
- 長時間、説明や途中報告なしで黙り込まない。
- ユーザーへ逐一確認を求めず、合意済み条件の範囲で分析を継続する。
- 途中報告は進捗と主要数値に限定し、失敗候補を一つずつ報告しない。
- 全ゲート通過前に完成したと表現しない。
