# レース探偵・絶対条件

最終更新: 2026-08-06

この文書は、ChatGPTの会話履歴が欠落しても参照できるようにGitHubへ恒久保存する。今後の分析・実装・本番反映では、この文書と `config/race-tantei-fixed-constraints.json` を最優先する。

## 1. 購入対象レース数

- 各開催日・各会場で、購入対象を5レース未満にしてはならない。
- 5レースは最低数であり、6レース以上に増やすことは認める。
- 回収率を見かけ上高くする目的で、対象レース数を5未満へ絞ることは禁止する。

## 2. コースと購入額

- ライト: 1レース2,000円
- スタンダード: 1レース5,000円
- プレミアム: 1レース10,000円
- 各コースは指定額を使い切る。
- 3コースを同一の買い目構成へ統一してはならない。

## 3. 買い目の分散

- 単勝だけへ絞ることは禁止する。
- ライトは単勝・ワイド・馬連をすべて含める。
- スタンダードは単勝・ワイド・馬連・馬単・3連複をすべて含める。
- プレミアムは単勝・ワイド・馬連・馬単・3連複・3連単をすべて含める。
- 高配当1点だけへ資金を集中させ、回収率を作ることは禁止する。

## 4. オッズと検証データ

- 買い目選定に使うオッズは、JRAが公開した実オッズだけとする。
- 単勝オッズから他券種のオッズを計算する処理、想定オッズ、推定オッズは禁止する。
- 取得できない過去オッズを後から補完・推測・捏造してはならない。
- 精算はJRAの実際の払戻金だけを使う。
- 結果、着順、払戻金を見た後に条件を決める後付け最適化は禁止する。

## 5. モデルの作成・実装順序

- 目標回収率は200%以上であり、100%へ引き下げない。
- 先に本番モデルを実装してから、回収率を確認する進め方は禁止する。
- 開発用コードで候補を探索し、未使用期間を含む全ゲートを通過した候補だけを承認する。
- 各コースの最終未使用期間回収率が200%以上でなければ、本番モデルとして実装・昇格・配信してはならない。
- 最低レース数、券種分散、固定購入額、公式オッズ限定、データ漏洩禁止の全条件を同時に満たす必要がある。
- 不合格候補は分析結果として記録してよいが、本番コード・本番設定・本番買い目へ反映してはならない。

## 6. 報告と進行

- 作業を始める前に、これから行う内容と所要時間の目安を説明する。
- 30分以上、説明や途中報告なしで黙り込まない。
- ユーザーへ逐一確認を求めず、合意済み条件の範囲で分析を継続する。
- 途中報告は進捗と主要数値に限定する。
- 最終報告は、採用できる結果、または不採用と判断した根拠となる結果を明示する。

## 7. 優先順位

この文書と機械判定用設定が、過去の分析スクリプト、古い本番設定、古い会話内容と矛盾する場合は、この文書を優先する。
